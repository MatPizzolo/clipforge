# Studio S3c: account workspaces, implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** build S3c in four deployable parts, each its own card (owner ruling, log #257):
- **S3c-1a:** data and routes (versioned setup, preview, import and verify; nothing visible).
- **S3c-1b:** pages (Map, workspaces, Style, Setup & History, notes).
- **S3c-2:** the clip producer reads the setup.
- **S3c-3:** experiments and results.

**Architecture:**
- **Every setup level is a flat map of registry paths.** Categories, blueprints and accounts store versions as `{path: value}` maps keyed by field-registry paths (spec §1.4). Saves validate path by path.
- **A pure resolver merges the levels.** It merges category → blueprint → account and returns every value with its origin. A projection writes the result back onto S1's `accounts` columns, so S1 and S2 readers don't change.
- **One service writes versions.** `accounts/versions.py` writes every version, inside a transaction that first recomputes the one dry run (`accounts/preview.py`). It rewrites the posting schedule copy after the commit.
- **Experiments and results are derived on read.** Only start, stop and decide write. They push the hooks freeze in the same transaction.
- **S2 and S3 take S3c's values through injection points their plans define.** S2's `FormatWindowSource` and `DigestProvider`, and S3's `needs_providers`, are wired in `runtime.build_deps`, and S3c's routers are appended to S3's `admin_routers`. No S2 module and no S3 module under `needs/` is edited.

**Tech Stack:**
- Python 3.12 (`uv`), pydantic v2, SQLAlchemy 2 Core + psycopg 3, Alembic, FastAPI;
- Next.js (S3a's shell, S3's admin client), Playwright and vitest;
- Modal (`app.py` only);
- pytest with the local Postgres fixture (`tests/dbfixture.py`).

**Spec:** [docs/superpowers/specs/2026-09-30-studio-s3-workspaces-design.md](../specs/2026-09-30-studio-s3-workspaces-design.md) (accepted 2026-09-30, revised by card 018 on 2026-10-02 and approved at its checkpoint A). Read it with this plan: section numbers below (§N) are the spec's. Also read:
- the S3 dashboard spec §7.3, §7.4, §8.4, §8.5, §8.7;
- the S2 plan's Tasks 2, 3, 6 and 23, as amended for the owner's option (a) (log #142, #261).

## Review Focus

The five conditions the spec implies but no task's main tests exercise, most likely first. Each has its pinning test in the owning task.
1. **A restore or save that names a prompt version that is no longer released** (removed from `prompts/metadata.json` after the version was saved): the owner expects a 422 naming the prompt ("keywords_v1 is not a released prompt"), and no new version. A broken job later is not acceptable. *Pinned in Task 4* (`test_restore_with_unreleased_prompt_is_refused`).
2. **"Apply to accounts" where one ticked account's projected schedule no longer passes S1's check** (its posting chat was removed from `TELEGRAM_ALLOWED_USER_IDS`): the owner expects the whole apply refused, naming that account, with nothing written for any account and no schedule copy rewritten. *Pinned in Task 4* (`test_apply_refuses_all_when_one_schedule_fails`).
3. **A job created with `SETUP_SOURCE=db` for an account that has no current version** (an account created on an old code path, or a failed version-1 write): the owner expects the job to run on today's constants with a warning, never to fail. *Pinned in Task 12* (`test_create_job_without_current_version_uses_constants`).
4. **An item-count experiment that never fills its window** (the account is paused for weeks): the owner expects "running, 0 of 30 items" with Stop available. The experiment must not slide into "needs a decision" with no data. *Pinned in Task 18* (`test_items_window_never_closes_without_items`).
5. **`setup import` run again after the owner has already saved version 2 of an account:** the owner expects the import to skip that account (it already has versions) and `verify` to compare against version 2's projection. Version 1 must not be duplicated, and `verify` must not report the edit as a difference. *Pinned in Task 6* (`test_reimport_after_edit_skips_and_verifies_clean`).

```python
CATEGORY_CODES = ("clips", "story", "band", "avatar", "model")
Level = Literal["category", "blueprint", "account"]
ChangeClass = Literal["live", "recut", "format", "rules", "identity"]
ACTOR = (r"^(telegram:[0-9]{1,20}|web:[A-Za-z0-9-]{1,39}|session:[a-z0-9][a-z0-9-]{0,39}"
         r"|cli:[A-Za-z0-9._-]{1,32}|system:[a-z]([a-z-]{0,38}[a-z])?)$")

class SetupTarget(Contract):
    kind: Level
    id: str

    @model_validator(mode="after")
    def _id(self) -> SetupTarget:
        ok = self.id in CATEGORY_CODES if self.kind == "category" else re.fullmatch(ACCOUNT_ID, self.id)
        if not ok:
            raise ValueError(f"unknown {self.kind} {self.id!r}")
        return self

class SetupVersion(Contract):
    target: SetupTarget
    n: int = Field(ge=1)
    values: dict[str, JsonValue]
    author: str = Field(pattern=ACTOR, max_length=80)
    note: str = Field(min_length=1, max_length=500)
    created_at: datetime
    experiment_id: int | None = None
    category_version: int | None = None   # accounts only
    blueprint_version: int | None = None  # accounts only
    format_changed: bool = False          # accounts only

class EffectiveValue(Contract):
    path: str
    value: JsonValue
    origin: Level
    change_class: ChangeClass
    replaces: list[tuple[Level, JsonValue]] = Field(default_factory=list)

class EffectiveSetup(Contract):
    account_id: str
    version: int
    category_version: int
    blueprint_version: int
    values: dict[str, EffectiveValue]

class DiffEntry(Contract):
    model_config = ConfigDict(populate_by_name=True)
    path: str
    from_: JsonValue = Field(None, alias="from")
    to: JsonValue
    change_class: ChangeClass

class FieldError(Contract):
    path: str
    msg: str
```

```python
# src/clipforge/accounts/versions.py
class VersionsService:
    """The one writer of setup versions and the projected `accounts` columns (S3c spec §5.3).
    Every write recomputes the dry run (preview.compute) inside its transaction and refuses
    when it is blocked, then rewrites each changed account's schedule copy after the commit."""

    def save(self, target, expected_version, proposed, note, actor, now, *, accounts=None,
             confirm_loosen=False) -> SaveResult:
        actor = _checked(actor)
        written: list[Account] = []
        with self.db.begin() as conn:
            current = self.repo.current(conn, target)
            if current is not None and current.n != expected_version:
                raise VersionConflict(current.n)
            req = PreviewRequest(target=target, expected_version=expected_version, proposed=proposed,
                                 accounts=accounts, confirm_loosen=confirm_loosen)
            result = preview.compute(conn, self.settings, req, now)     # raises SetupInvalid on errors
            if result.blocked:
                raise SetupBlocked([b.code for b in result.blocked], result.blocked[0].experiment_id)
            version = self.repo.insert(conn, _next(current, target, proposed, note, actor, now))
            if target.kind == "account":
                written.append(self._project(conn, target.id, now))
            else:
                for account_id in result.affected.accounts:            # the ticked ones, minus skipped
                    self._adopt(conn, account_id, target, version, actor, now)
                    written.append(self._project(conn, account_id, now))
        self._publish(written)                                           # after the commit
        return SaveResult(...)

    def _project(self, conn, account_id, now) -> Account:
        setup = self.repo.effective(conn, account_id)
        account = project(AccountsRepo(self.db).get_in(conn, account_id), setup)
        account = account.model_copy(update={"posting": _checked(account.posting, self.settings)})
        AccountsRepo(self.db).write_projection(conn, account, now)
        return account

    def _publish(self, accounts: list[Account]) -> None:
        if self.kv is not None:
            autopilot = AutopilotRepo(self.db)
            for account in accounts:
                write_schedule_copy(self.kv, account, autopilot.get(account.id) or hands_on(account))
```

- `_checked` raises S1's `AccountError`. Convert it to `SetupInvalid([FieldError(path=f"{account_id}.posting", msg=str(exc))])`, so the transaction rolls back for every account in an apply.
- `_adopt` writes the account's next version pinned to the new parent version, with the note `"adopts <kind> <id> v<n>"`. Its `format_changed` comes from `format_changed(previous_effective, new_effective)`.
- `_next` builds the full snapshot: the current values merged with `proposed`, where `None` deletes an override (Reset).
- A `rules.*` change that removes a required tag or disclosure, or turns `require_credit` off, needs `confirm_loosen`. Without it, the error is `FieldError(path, "loosening a rule needs confirm_loosen")`.
- `restore` loads version `n`'s values and calls `save` with them and the note `"restores v<n>: <note>"`.
- `create_account_v1` inserts version 1 for an account S1's create has just inserted, in the same transaction (Task 6 wires it).

In `db/accounts.py`:
- Add `write_projection(conn, account, now)`. It updates the projected columns and `current_version` only, and it is the only path to them once an account has a version.
- `AccountsRepo.update` keeps working for the columns S1 and S2 still own (`publisher`, and the legacy `review_tier` and `monthly_budget_usd`). It raises `RuntimeError("versioned accounts change their setup through accounts/versions.py")` only when `current_version` is set **and** a projected column (`blueprint`, `blueprint_version`, `kind`, `language`, `niche`, `platforms`, `brand`, `posting`, `paired_account_id`, `persona_id`) differs from the stored row.
- S2's publisher edit (`--publisher-profile`, `--facebook-page-id`, `--clear-publisher`) therefore keeps its path and writes no version.

```python
def format_window(self, account_id: str) -> tuple[int, int] | None:
    with self.db.begin() as conn:
        n = conn.execute(select(func.max(account_versions.c.n)).where(
            account_versions.c.account_id == account_id, account_versions.c.format_changed)).scalar()
        if n is None:
            return None
        decided = conn.execute(
            select(func.count(func.distinct(content_items.c.id)))
            .select_from(content_items.join(post_events, post_events.c.item_id == content_items.c.id))
            .where(content_items.c.account_id == account_id, content_items.c.setup_version >= n,
                   post_events.c.kind.in_(("approved", "reviewed")),
                   ~post_events.c.actor.startswith("system:"))).scalar_one()
    return n, int(decided)
```

```python
from typing import Protocol

from sqlalchemy import Connection


class HookFreezer(Protocol):

    def release(self, conn: Connection, account_id: str, experiment_id: int) -> None: ...


class NoHookFreezer:
    """Until the hooks build deploys: nothing to freeze."""

    def release(self, conn: Connection, account_id: str, experiment_id: int) -> None:
```
