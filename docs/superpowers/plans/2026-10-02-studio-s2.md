# Studio S2: publishing and autopilot, implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build S2 in three deployable steps:
- **S2a:** rails, with the assisted flow unchanged.
- **S2b:** Upload-Post publishing for realtalk on Hands-on.
- **S2c:** autopilot, the digest, failure rows, tracking links, and the launch of founder.tapes and hombre.en.construccion.

**Architecture:**
- One `dispatcher` cron (ADR-27) replaces `posting_tick`. From Dict state alone it decides which per-slot phases (`plan`, `card`, `handoff`) and fleet tasks (`digest`, `publish_reconcile`) are due, and it opens Postgres only for those.
- Publishing state lives on the `posts` rows, moved by forward-only conditional updates in one module (`publishing/state.py`).
- `UploadPostPublisher` and `AssistedPublisher` sit behind one `Publisher` protocol. A durable claim per (item, platform) means they can never both publish one.
- Review routing, the gate and the ladder are pure functions over counted stats. Every write carries an actor.

**Tech Stack:** Python 3.12 (`uv`), pydantic v2, SQLAlchemy 2 Core + psycopg 3, Alembic, FastAPI, httpx, python-telegram-bot (webhook mode), Modal (`app.py` only), pytest with the local Postgres fixture (`tests/dbfixture.py`).

**Spec:** [docs/superpowers/specs/2026-10-01-studio-s2-design.md](../specs/2026-10-01-studio-s2-design.md) (approved by the coordinator on 2026-10-02 with its re-review changes in). Read it with this plan: section numbers below (§N) are the spec's.

## Global Constraints

- **Workflow:**
  - Work only from the S2 build card. **Sessions never commit, push, deploy or stop the app.**
  - Each task's last step is "check and record" (`scripts/check.sh` green, the task noted in the card's report). The owner commits at the card's checkpoints with the suggested message.
- **Python:**
  - `uv` only, never pip.
  - New dependencies: none. httpx, SQLAlchemy, psycopg, FastAPI and pydantic are already locked; the Upload-Post SDK is **not** used (spec §1.2).
  - Stage modules are untouched. **Only `src/clipforge/app.py` imports `modal`.**
- **Contracts and data:**
  - Contracts change in `models.py` first (CLAUDE.md rule 2).
  - **One writer per key or column group** (ADR-14, ADR-41; spec §1.2's "Writes" column):

    | Writer | Writes |
    |---|---|
    | `publishing/state.py` | `posts` publish columns, `publishing:inflight:<ref>`, `publish:last_handoff` |
    | `dispatch/plan.py` | `slot_plans` |
    | `accounts/autopilot.py` | `autopilot`, `autopilot_events` |
    | `posting/actions.pause` | `brake:<scope>`, `posting_state` |
    | the accounts service | `accounts.publisher`, `posting:schedule:<account>` |
    | `review/service.py` | `content_items` review columns and `copy` |
    | `review/cards.py` | `review_messages` |
    | `tracking.py` | `links`, `clicks` |
- **Actors:** match `telegram:\d{1,20}`, `web:<login>`, `session:<name>`, `cli:<user>` or `system:[a-z][a-z-]{0,39}`. The new system actors are `system:autopilot`, `system:demotion`, `system:upload-post`, `system:daily` and `system:migration`.
- **Migrations:**
  - S2's migration takes the next number after the head on `main`, and moves `EXPECTED_HEAD` in `db/doctor.py`.
  - It carries `jobs.error`, `post_events.actor` (backfilled) and `posting_state.changed_by`/`reason`, **unless** a migration that already carries them has landed (S3 spec §8.7).
  - Expand-only. `0001` is frozen.
- **The Dict stays current until S1 Task 23** (spec §3.1):
  - "Posted" is always written through `PostingRepo.set_posted` (Dual).
  - `posting verify` must stay at 0 differences.
- **Upload-Post:**
  - Base URL `https://api.upload-post.com`, header `Authorization: Apikey <key>`.
  - `disable_inbox_fallback=true` always; `privacy_level` never sent.
  - The key is `sha256("<item_id>|<sorted platforms>|<attempt>").hexdigest()[:32]`, sent as `Idempotency-Key` and `request_id`.
- **`GATE_ENFORCE`** (`off` by default): in S2a the gate only logs and stamps its violations, and never holds or routes an item. The owner turns it `on` in S2b, after `clipforge policy dry-run` reports "0 items would be held" (Task 8).
- **Secrets** are added with the procedure in `docs/ops/secrets.md` (a dashboard edit that adds only the new keys). Never `modal secret create --force`, which replaces the whole secret.
- **Every owner deploy:** `scripts/deploy.sh --dry-run` first, then the deploy outside the blackout (runbook §1).
- **`RECOVERY_WINDOW_S`** defaults to **0** (no re-send) until R5 confirms Upload-Post keeps a key for at least 10 minutes. It is never lowered "to fit".
- **Times:**
  - Planning at **08:50** and the digest at **09:00**, in the owner's time zone (`OWNER_TIMEZONE`, else `POSTING_TIMEZONE`), for every account. Slots keep each account's own time zone.
  - The plan's horizon: to the next plan plus **2.5 h**.
  - Hand-off at **S − 30 min**; 2 h cards at **S − 2 h**; `SLOT_WINDOW` stays **30 min**.
  - Final failure when a row is still unresolved **60 min after the slot**.
  - Reconcile every **15 min** while `publish:last_handoff` is under **26 h** old, and daily.
  - A row is stuck in `claimed` after **2 min**.
- **Telegram:**
  - Posting cards keep `p:` callbacks; review cards use `r:ok|rej|why`.
  - The 09:00 batch is **exempt** from the 20-an-hour cap and paced at **≤ 1 message/second**, honouring a 429's `retry_after`.
  - One-tap only for review cards and the brake (#427).
- **Security** (rule 8): never log the Upload-Post key, the webhook secret, a signed media link or an Upload-Post response body. The webhook verifies the HMAC with `hmac.compare_digest` and a 5-minute timestamp window. A missing secret answers 503.
- **Tests:**
  - DB tests use the `db` fixture and **fail, never skip**, without Postgres.
  - Network calls are mocked (httpx `MockTransport`, `FakePublisher`, the bot fakes in `tests/bot/fakes.py`).
  - Fast tests only; the R5 call is a throwaway probe, not a test.
- **Account ids in commands and tests:** `realtalk-clips-en`, `founder-tapes-en`, `hombre-en-construccion-es`.

## Review Focus

The five conditions the spec implies but no task's main tests exercise, most likely first. Each has its pinning test in the owning task.
1. **An approve tapped after the slot is gone** (later than S + 30 min, or on an item already handed off): the owner expects "missed: this item leads the next plan", not an error or a second post. *Pinned in Task 15* (`test_late_approve_after_window_says_missed`).
2. **The media file is gone when Upload-Post fetches it** (the Volume was cleaned, or the item's video went missing): Upload-Post reports a failure. The owner expects one `publish_failed` row and the item marked unavailable, not a fallback card with a missing video. *Pinned in Task 18* (`test_fallback_with_missing_video_marks_unavailable`).
3. **A DST change between planning and the slot** (an account in America/New_York, the owner in Europe/Madrid, on a DST weekend): the owner expects each slot planned once, at its local wall-clock time, with no slot missing or doubled. *Pinned in Task 14* (`test_plan_across_dst_change`).
4. **A review card tapped from another chat, or by a user not in `TELEGRAM_ALLOWED_USER_IDS`:** the owner expects nothing to change, and the tap answered silently. *Pinned in Task 15* (`test_review_tap_from_other_chat_changes_nothing`).
5. **Upload-Post accepts some platforms and rejects others in one call** (YouTube's daily cap of 10 hit, the others fine): the owner expects the accepted ones scheduled, the rejected one retried, and one item rather than two. *Pinned in Task 16* (`test_partial_accept_schedules_some_retries_one`).

ACTOR_CHECK = (r"actor ~ '^(telegram:[0-9]{1,20}|web:[A-Za-z0-9-]{1,39}"
               r"|session:[a-z0-9][a-z0-9-]{0,39}|cli:[A-Za-z0-9._-]{1,32}"
               r"|system:[a-z]([a-z-]{0,38}[a-z])?)$' and length(actor) <= 80")

def upgrade() -> None:
    op.add_column("jobs", sa.Column("error", sa.Text))
    op.add_column("post_events", sa.Column("actor", sa.Text))
    op.execute("update post_events set actor = data->>'actor' where data ? 'actor'")
    op.create_check_constraint("ck_post_events_actor", "post_events", f"actor is null or ({ACTOR_CHECK})")
    op.add_column("posting_state", sa.Column("changed_by", sa.Text))
    op.add_column("posting_state", sa.Column("reason", sa.Text))

# src/clipforge/accounts/autopilot.py
PRESETS: dict[Preset, dict[str, object]] = {
    "hands_on":   {"produce": False, "review_dial": "review", "publish": True, "scale": False},
    "supervised": {"produce": True,  "review_dial": "sample", "publish": True, "scale": False},
    "autopilot":  {"produce": True,  "review_dial": "auto",   "publish": True, "scale": True},
}
FIELDS = {"produce", "review_dial", "publish", "scale", "runway_days", "batch_line_usd", "monthly_cap_usd"}

class AutopilotError(ValueError): ...

class AutopilotService:
    """The one writer of `autopilot` and `autopilot_events` (ADR-48, spec §5.4)."""
    def __init__(self, db: Database, accounts: AccountsRepo, kv: KV) -> None: ...
    def get(self, account_id: str) -> Autopilot:
        row = AutopilotRepo(self.db).get(account_id)
        if row is not None:
            return row
        account = self.accounts.get(account_id)
        if account is None:
            raise AutopilotError(f"no account {account_id}")
        return hands_on(account)
    def set(self, account_id, field, value, actor, reason, now) -> Autopilot:
        if field not in FIELDS:
            raise AutopilotError(f"unknown control {field}")
        if field == "review_dial" and not actor.startswith("system:") and not (reason or "").strip():
            raise AutopilotError("a change to the Review dial needs a reason")
        before = self.get(account_id)
        changes = {field: value}
        preset = _preset_of({**before.model_dump(), **changes})
        if preset != before.preset:
            changes["preset"] = preset
        return self._write(before, changes, actor, reason, now)
    def apply_preset(self, account_id, preset, actor, reason, now) -> Autopilot:
        before = self.get(account_id)
        if before.review_dial != PRESETS[preset]["review_dial"] and not actor.startswith("system:") \
                and not (reason or "").strip():
            raise AutopilotError("a change to the Review dial needs a reason")
        return self._write(before, {**PRESETS[preset], "preset": preset}, actor, reason, now)
    def _write(self, before, changes, actor, reason, now) -> Autopilot:
        after = before.model_copy(update={**changes, "updated_by": actor, "updated_at": now})
        AutopilotRepo(self.db).upsert_with_events(before, after, actor, reason, now)  # one transaction
        if before.publish != after.publish:
            write_schedule_copy(self.kv, self.accounts.get(after.account_id), after)
        return after

def _preset_of(values: dict[str, object]) -> Preset:
    for name, controls in PRESETS.items():
        if all(values[k] == v for k, v in controls.items()):
            return name
    return "custom"
```

- Account create inserts `hands_on(account)` and its seed event, with the creating actor.

"""The policy gate v1 (spec §5.1): pure checks; any violation sends the item to review."""
AI_KINDS = {"generated", "music_generated"}

def gate(item, account, source, copy, others, *, require_credit, platforms, now) -> GateResult:
    out: list[Violation] = []
    if any(a.kind in AI_KINDS for a in item.assets) and not item.ai_disclosure:
        out.append(Violation(code="missing_ai_label", message="AI-made media without the AI label"))
    for p in platforms:
        c = copy.get(p)
        if c is None:
            continue
        if item.sponsored and "ad" not in [t.lower() for t in c.hashtags] and "#ad" not in c.text.lower():
            out.append(Violation(code="missing_ad", platform=p, message="sponsored without #ad"))
        needs_credit = require_credit or (source is not None and source.kind == "channel")
        if needs_credit and source is not None and source.credit_name not in c.text:
            out.append(Violation(code="missing_credit", platform=p, message=f"credit '{source.credit_name}' missing"))
    for a in item.assets:
        if a.kind == "source_video":
            if source is None or source.permission.type is None:
                out.append(Violation(code="license_unrecorded", message="source video without a recorded permission"))
        elif not a.license or a.license == "unrecorded":
            out.append(Violation(code="license_unrecorded", message=f"{a.kind} asset without a license"))
    if any(o.account_id != item.account_id and _iou(o, item) > SAME_MOMENT_IOU for o in others):
        out.append(Violation(code="cross_account_duplicate", message="the same moment is on another account"))
    if (reason := hold_reason(source, platforms, now)) is not None:
        out.append(Violation(code="source_held", message=reason))
    return GateResult(violations=out)

# src/clipforge/review/routing.py
PRODUCER_WINDOW, FORMAT_WINDOW, DUB_WINDOW = 5, 10, 10
SPONSORED_DAYS = timedelta(days=30)
SPOT_EVERY = 9                      # 9 auto items since the last check -> the next is a check
SPOT_WEEKLY, SPOT_GAP = 3, timedelta(hours=24)

def route(item, autopilot, gate_result, counts, spot, *, first_post_at,
          paired_account_id, parent_account_id, now) -> Routing:
    reasons: list[ReviewReason] = []
    window: str | None = None
    if gate_result.violations:
        reasons.append("gate")
    if item.sponsored and (first_post_at is None or now - first_post_at < SPONSORED_DAYS):
        reasons.append("sponsored")
    done = counts.producer.get(item.producer_version, 0)
    if done < PRODUCER_WINDOW:
        reasons.append("producer_window"); window = f"producer:{item.producer_version}:{done}/{PRODUCER_WINDOW}"
    if counts.format_version is not None and counts.format_count < FORMAT_WINDOW:
        reasons.append("format_window"); window = window or f"format:v{counts.format_version}:{counts.format_count}/{FORMAT_WINDOW}"
    if item.parent_item_id and parent_account_id and parent_account_id == paired_account_id \
            and counts.dubs_in_pair < DUB_WINDOW:
        reasons.append("dub_window"); window = window or f"dub:{counts.dubs_in_pair}/{DUB_WINDOW}"
    dial = autopilot.review_dial
    if dial == "review":
        reasons.append("dial")
    elif dial == "sample" and _spot_check(spot, now):
        reasons.append("spot_check")
    lane = "review" if reasons else "auto"
    return Routing(lane=lane, reasons=reasons, dial=dial, window=window, gate=gate_result)

def _spot_check(spot: SpotState, now: datetime) -> bool:
    if spot.auto_since_last >= SPOT_EVERY:
        return True
    return spot.checks_last_7d < SPOT_WEEKLY and (spot.last_check_at is None or now - spot.last_check_at >= SPOT_GAP)

def tick(ctx: DispatchCtx, now: datetime) -> list[str]:
    if ctx.ops is not None:
        ctx.ops.flush(now)                                    # ADR-45 fold (ADR-27's decision)
    posting = ctx.posting                                     # posting/backend.Posting, as the old tick used
    if posting.problem is not None:                           # kept from posting_tick: misconfigured = off
        if ctx.ops is not None:
            ctx.ops.alert(f"Posting is off: {posting.problem}", "posting", "problem", now=now)
        return [f"off: {posting.problem}"]
    if (since := outage_since(ctx.kv)) is not None:           # kept from posting_tick (#217)
        return [f"outage since {since}: restore, check /status, then /go"]
    # all_schedules(): the Dict copies in postgres mode, the env account in dict mode (no DATABASE_URL)
    schedules = {k: ScheduleCopy.of(v) if not isinstance(v, ScheduleCopy) else v
                 for k, v in posting.all_schedules().items()}
    view = DispatchView(now=now, schedules=schedules, brakes=brake.touch_all(ctx.kv), outage=None,
                        problem=None, last_handoff=_last_handoff(ctx.kv),
                        owner_zone=ctx.settings.owner_zone())
    lines: list[str] = []
    for task in ctx.registry:
        for key in task.due(view):
            claim = f"dispatch:{task.name}:{key}"
            if not ctx.kv.put(claim, now.isoformat(), skip_if_exists=True):
                continue
            try:
                if task.spawn:
                    ctx.spawn(task.name, key); lines.append(f"{key}: spawned {task.name}")
                else:
                    lines.append(f"{key}: {task.run(ctx, key)}")
            except Exception as exc:
                ctx.kv.delete(claim)
                log.warning("dispatch %s %s failed: %s", task.name, key, redact(exc))
                if ctx.ops is not None:
                    ctx.ops.alert(f"Dispatcher task {task.name} failed: {redact(exc)}", "dispatch", task.name, now=now)
                lines.append(f"{key}: error")
    return lines or ["idle"]

# src/clipforge/publishing/keys.py
def publish_key(item_id: str, platforms: list[Platform], attempt: int) -> str:
    joined = ",".join(sorted(p.value for p in platforms))
    return hashlib.sha256(f"{item_id}|{joined}|{attempt}".encode()).hexdigest()[:32]
```

```python
# src/clipforge/db/publishing.py (the claim; other transitions follow the same shape)
CLAIM = text("""
    update posts set publisher='upload_post', state='claimed', claimed_at=:now, attempts=1,
           request_id=:key, copy=cast(:copy as jsonb)
    where item_id=:item and platform = any(:platforms) and publisher is null and state='pending'
    returning platform""")
RETRY = text("""
    update posts set state='claimed', claimed_at=:now, attempts=attempts+1, request_id=:key
    where item_id=:item and platform=:platform and publisher='upload_post'
      and state='retrying' and attempts < 3
    returning attempts""")
FALLBACK = text("""
    update posts set publisher='assisted', state='fallback'
    where item_id=:item and platform=:platform and publisher='upload_post'
      and state in ('failed','scheduled')
    returning platform""")
```

Notes on the transitions:
- `claim` computes the key for attempt 1 from the requested platforms. The stored `request_id` is the same for every row claimed in one call.
- Each transition inserts a `post_events` row (`claimed`, `scheduled`, `retrying`, `failed`, `published`, `fallback`, `cancelled`, `uncancelled`) in its transaction, with actor `system:upload-post` for Upload-Post results and `None` for system transitions.
- `retry_claim` computes the new key from the incremented attempt. When `RETRY` returns nothing and the row is `retrying` at 3 attempts, it calls `to_failed`.
- `PublishStore` calls `_marker(ref)` after every transition. It sets `publishing:inflight:<ref>` while any row of the item is `claimed`, `scheduled`, `retrying` or `failed` with `publisher='upload_post'`, and deletes it otherwise.
- `record_receipt` writes `publish:last_handoff = now.isoformat()`.
- `published` updates the row (`state='published'`, `external_id`, `url`), then calls `self.posting_repo.set_posted(ref, platform, True, at, actor="system:upload-post")`.
