# Studio S5: media servers and producer registry, implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build S5 in four deployable steps (four build cards; LLM tracing left S5 by the owner's ruling, log #597):
- **S5-1:** `app.py` split into a `modal_app/` package; nothing changes live.
- **S5-2:** the producer registry and one engine; clips run on it unchanged.
- **S5-3:** `media/` (protocols, fakes, `registry.toml`), the `narrate`, `stills` and `music` stages, and the renderer additions; no live change.
- **S5-4:** weight functions, the media servers and the hello producer; hello runs end to end on Modal.

**Architecture:**
- Producers are data (`producers/registry.py`): a list of `StepDef`s plus one handler per step. One Modal-free engine (`pipeline/engine.py`, from today's `steps.py`) runs the guard, hand-off, fan-out, fan-in, failure path, resume and sweeper for every producer.
- Media models run as `modal.Cls` servers whose GPU, image, snapshot mode, window and container cap come from `media/registry.toml`. A GPU step runs inside its server as `run_step`, one item per call. Stage logic stays Modal-free and talks to `media/` protocols; real model adapters (`media/impl/`) import their heavy libraries lazily.
- The renderer gains optional crossfades and a duck envelope whose defaults leave every clip Timeline's key and graph unchanged.

**Tech Stack:** Python 3.12 (`uv`), pydantic v2, Modal 1.5.5 (`app.py` + `modal_app/` only), ffmpeg 6.1 locally / 5.1 in the Modal image, pytest; in the server images only (not in `uv.lock`): torch 2.10.0 + torchaudio 2.10.0, qwen-tts, faster-whisper 1.2.1 / ctranslate2 4.8.2 / av 17.0.0, diffusers 0.40.0, transformers, accelerate, peft, ACE-Step 1.5 (`v0.1.6`).

**Spec:** [docs/superpowers/specs/2026-10-02-studio-s5-design.md](../specs/2026-10-02-studio-s5-design.md) (approved by the owner section by section on 2026-10-02, reviewed as a file at checkpoint A). Section numbers below (§N) are the spec's.

## Global Constraints

- **Workflow:**
  - Work only from an S5 build card. **Sessions never commit, push, deploy, stop the app, change a secret or run Alembic.** The owner does, from the commands each checkpoint gives.
  - Each task's last step is "check and record": `scripts/check.sh` green, the task noted in the card's report. The owner commits at the card's checkpoints.
  - S5's build starts after card 010 (S1's rollout). Every code card is deployed before the next code card merges (log #144), so S5's checkpoints take turns with the S2 and S3 cards.
- **Modal boundary:** only `src/clipforge/app.py` and `src/clipforge/modal_app/**` import `modal` (a test). Stage modules, `pipeline/`, `producers/` and `media/` never do (CLAUDE.md rule 1).
- **Licenses:** no model, weights, code or bundled dependency outside `media/registry.toml`'s allowlist is downloaded or loaded (ADR-30; 03's allowlist). A `review` license needs an `owner_ruling`; GPL-3.0 needs its server-only `condition`.
- **Clips don't change** (spec §6.4, §8.3): step names, Modal function names and timeouts, Dict keys, stage modules, cache keys, `producer_version`, rendered output. `render.STAGE_VERSION` stays `"4"`; if a golden or pinned clip test moves, stop and ask (the bump opens ADR-49's window).
- **Contracts change in `models.py` first** (rule 2), and every change is additive: old Dict records and API clients must still validate.
- **Cost (rule 7):** every new stage records GPU seconds, GPU type and USD through `ctx.record_cost`. **Progress (rule 3):** every new stage calls `ctx.report` per line, image or bed.
- **No secrets in code or logs** (rule 8). S5 adds no secret. **No LLM tracing in S5** (log #597): no Langfuse code, no `LLMClient` change.
- **Weights:** servers mount `clipforge-models` read-only, set `HF_HUB_OFFLINE=1` and never download; only `modal_app/weights.py` writes the models Volume. No Hugging Face token is needed for S5's models.
- **Cost caps per build card** (log #605): S5-1 $0.05, S5-2 $0.25, S5-3 $0.25, S5-4 $5 (Modal and API spend by the session and the owner steps together; stop and ask before going over).
- **Probe and spike apps:** any probe a session runs has its own app name and is stopped before the session ends (`uv run modal app list` shows none running). Nothing touches the `clipforge` app except the owner's deploys.
- **Every owner deploy:** `scripts/deploy.sh --dry-run` first, then `scripts/deploy.sh --reason "<why>"` outside the blackout (runbook §1).
- **ffmpeg:** render tests that touch the graph also run in a `debian:bookworm` container (ffmpeg 5.1) before the deploy (03; S4's lesson).
- **New dependencies:** none in `uv.lock`. Server-only packages are pinned in `registry.toml` and installed in their images, not in `uv.lock`; mypy ignores their imports (`pyproject.toml` overrides, as for faster-whisper today).

## Review Focus

The five conditions the spec implies but no task's main tests exercise, most likely first. Each has its pinning test in the owning task.
1. **A job submitted just before the S5-2 deploy and finishing after it** (its `job:<id>` record has no `producer` field, and its next step is spawned by old code into the new functions): the owner expects it to finish as a clips job, with its clips posted as before. *Pinned in Task 4* (`test_old_job_record_without_producer_finishes_as_clips`).
2. **The owner submits a hello job with a source URL, or a clips job with `params`:** the owner expects a 422 with a clear message, not a job that fails at its first step. *Pinned in Task 5* (`test_producer_input_rules_reject_mixed_inputs`).
3. **Weights missing or at another revision on the Volume** (a prep never ran, or the registry moved to a new revision before `weights --model` ran): the owner expects the step to fail at once with "weights missing: run `weights --model <id>`" and one ops alert, not three retries that each pay a cold start. *Pinned in Task 14* (`test_manifest_mismatch_is_permanent`).
4. **A crossfade on a Timeline whose neighbour is shorter than the fade** (a 0.3 s still next to a 0.4 s crossfade): the owner expects a validation error naming the segment when the producer builds the Timeline, not an ffmpeg failure at render. *Pinned in Task 10* (`test_crossfade_longer_than_a_neighbour_is_rejected`).
5. **A narration line that is a single word, or only a number** ("Nineteen-nineteen."): the guard's expected duration must not reject a correct short chunk. The owner expects short lines to pass. *Pinned in Task 8* (`test_guard_accepts_short_lines`).
