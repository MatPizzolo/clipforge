8. **Deviations:**
   - **The `main`-push base is the last successful `ci.yml` push run on `main`, not `github.event.before`** (action 2).
     - Why: with `before`, a code push that fails `check` followed by a docs-only push would pass `check` on the docs tests alone. The deploy job diffs against the last *successful* run, so it would then deploy the untested code.
     - Using the deploy job's own base closes that gap: no earlier successful run, or an unknown commit, counts as code.
     - Cost if wrong: a docs-only merge after a red `main` runs the full gate (a few minutes).
   - **`web.yml`'s `push` is limited to `main` too** (action 1 named only `ci.yml`), for the same one-run-per-commit reason. Its `paths:` filters are unchanged.
   - **`.gitignore` already had `scratch/`,** which ignores `scratch/` at any level. Adding `scratch/**` would change nothing, so the line only gained a comment.
   - **`test_every_card_branch_has_a_scope` moved from `tests/scripts/test_check_scope.py` to `tests/test_docs.py`.** It reads the real cards, and a card-only PR runs only the docs tests. Otherwise a card whose branch has no scope could merge green.
   - **The dependabot log range is written `[0, -1]`.** `check_scope.py` prints that as "range #0-#-1", which the test asserts.
   - **Coordinator review (2026-10-02), fixed on this branch:**
     - **B1:** `check` no longer skips when `changes` fails, since a skipped required check would merge green with nothing run. It has `if: ${{ !cancelled() }}`, a first step that exits 1 when `needs.changes.result != 'success'`, the code path on `code != 'false'`, and the docs path only on `code == 'false'`, so a missing output runs the whole gate. `tests/scripts/test_ci.py` allows exactly that one job-level `if` and checks the first step.
     - **S1:** a `main` push diffs two-dot against the last green commit, as the deploy job does, so a non-linear `main` can't hide a code change. PRs keep three dots. Tested with a side-branch history where three dots see nothing and two dots see the code.
     - **S2:** the docs-path fallback is in item 6.
     - **Minor:** the `.claude/` and `web/` Markdown note is in item 6.
   - **The ffmpeg apt cache is reverted to the plain install** (coordinator, after PR #37's second code run).
     - `awalsh128/cache-apt-pkgs-action` restores files without running `postinst`, so the `libblas.so.3` update-alternatives link (made by `libblas3`'s `postinst`) was missing.
     - On its first cache hit, `ffmpeg -version` failed with `error while loading shared libraries: libblas.so.3`.
     - The step is back to `sudo apt-get update && sudo apt-get install -y --no-install-recommends ffmpeg`. The version and libass check stays, and the action and its SHA pin are gone.
     - Cost: the 18–36 s install stays on every code run (item 6).

9. **Open issues:**
   - **Follow-up for an `s1/` or `s2a/` card: wall-clock ordering bugs.**
     - **The `jobs` upsert** (`src/clipforge/db/jobs.py:33`). On a backward clock step, or clock skew between Modal containers, a DONE or FAILED summary is dropped without a word, and `GET /jobs/{id}` reads the stale `queued` row once the Dict expires. `posting_daily`'s backfill repairs only *missing* rows, not stale ones.
       - Proposed fix: let a terminal status always replace a non-terminal one:
         ```
         where=or_(jobs.c.updated_at <= excluded.updated_at,
                   and_(jobs.c.status.in_(["queued", "running"]),
                        excluded.status.in_(["done", "failed"])))
         ```
       - Log a warning when `upsert` returns `False` from `record_job`.
       - Regression test: the flow above, with `steps.utcnow` shifted back 2 s.
     - **The skip verdict** (`src/clipforge/posting/queue.py:40-44`, `status()`). `verdict.at >= last_send` misreads a skip as unanswered when the clock steps back, so a second ⏭ sends another clip.
       - Proposed fix: `posting/actions.py` stamps `at = max(now, latest send or verdict time on the record)`; or the verdict records the send it answers.
       - Regression test: the plugin above.
     - Until then, both tests stay flaky on WSL2. They are very unlikely to fail on GitHub's runners (no stepping clock seen there).
   - **pytest-xdist: not recommended yet.**
     - The gain is about 20–25% locally, eaten by one Postgres container per worker.
     - It also starts up to 12 containers on a laptop that runs several sessions.
     - Revisit with the clock fix in place and a shared container: one container for the session, one database per worker, created from `PYTEST_XDIST_WORKER` in `tests/dbfixture.py`. Then measure again.
     - If adopted, it needs `pytest-xdist` in `[dependency-groups].dev` (`pyproject.toml` + `uv.lock`, outside `x0/`'s scope) and `-n auto` in `scripts/check.sh`'s pytest step.
     - GitHub's `ubuntu-24.04` runners have 4 cores, so the CI gain would be smaller.
