6. **Decisions:** log #202 (the slot guard from sends) and #203 (the schedule copy, its one writer and the tick order). Choices not written down anywhere else:
   - The tick uses the database account row, not the copy, for the chat id and hashtags once a slot is due. The copy only decides *when*.
   - If writing the copy fails after the database write, `POST` or `PATCH /accounts` returns the error. Repeating the edit, or the daily `sync_schedules`, rewrites the copy. It isn't swallowed, because a stale copy would send at the old times.
   - In postgres mode, an account whose copy is missing isn't ticked until a create, edit or the daily sync writes it. Accounts are created through the API at rollout step 4c.3 while still in dict mode, so their copies exist before the 4c.7 switch.
   - The tick reads each copy with `get`, so the copies count as active every 5 minutes and won't expire (ADR-24).
