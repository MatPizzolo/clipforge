6. **Decisions:**
   - Decision-log rows #219 (doctor time zones), #220 (manual rebuild during an outage), #221 (video frame on Telegram sends), #222 (time-zone catches include `OSError`). No ADR, no roadmap tick.
   - Choices not written down anywhere else:
     - The outage check lives in `service.rebuild_posting` itself, not only in the route, so any future caller gets it too. `posting_daily` still checks first and never reaches the raise.
     - `doctor` exits non-zero only for the time-zone check. The other required local checks still just print, as before, so the change stays inside the card.
     - The GPU image checks the names from the local `.env`, not from `clipforge-secrets`. The runbook requires `.env` to match the secret for `POSTING_TIMEZONE`, and `gpu_doctor` has no secrets attached.
     - The posting assistant probes with `media_info` (display size after rotation), not `probe_info`. `ContentItem` has no width or height, and adding them would be a contract change for one Telegram hint. It costs one ffprobe per slot send (well under a second, on `base_image`, which has ffmpeg).
     - `duration` goes to Telegram in whole seconds, at least 1.
     - The notifier passes `RenderedClip.probe`'s width and height, which are the raw stream size, not corrected for rotation (`probe_info` doesn't apply rotation; `media_info` does). That's correct today because our renders carry no rotation. If a producer ever writes a rotated stream, switch the notifier to `probe_size(path)` like the posting assistant.
