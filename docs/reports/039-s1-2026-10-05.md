5. **Contract changes:**
   - Settings: new `Settings.state_reads_problem`. It is computed and never read from the environment. A `STATE_READS` value in any case or with spaces is now accepted.
   - New `cli.TIMEOUT_S`.
   - Telegram callback answers carry no text. Failures are now chat messages instead of toasts.
   - No models, STAGE_VERSION, cache keys, prompts, Dict keys, API routes or migrations.
6. **Decisions:**
   - Log rows #226 (bad `STATE_READS`), #227 (overview reads and CLI retry) and #228 (callbacks answered first, "not modified" silent). No ADR. No roadmap box (this is a follow-up, not a roadmap item).
   - Choices not written down anywhere else:
     - Only GETs are retried. A timed-out write may have happened, so it is never sent twice. This applies to every CLI GET, not only `status`, and the worst case is 120 s per call.
     - `not_modified` matches Telegram's message text, not `telegram.error.BadRequest` by type. That keeps `posting/actions.py` free of PTB types and works with the fake sender.
     - `tell(GONE)` stays, so a tap on a missing clip still explains itself. Repeated taps post one reply each.
